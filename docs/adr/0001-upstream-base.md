# ADR-0001 上游基线：官方 KernelSU

- 状态：已接受（2026-09-29，维护者决定）
- 责任：维护者 + 本地 CI
- 许可证基线：`kernel/` GPL-2.0-only，其余 GPL-3.0-or-later（与上游一致，不附加额外限制）

## 决策

以 **官方 KernelSU（tiann/KernelSU）** 为基线做二次开发。上游源码已取回本地：`upstream/KernelSU-main/`。

## 维护者理由

- 官方代码更纯粹、可审计、上游即生态标准。
- SUSFS 内核补丁生态（susfs4ksu）正是基于官方 KernelSU。
- 官方管理器界面朴素 → 美化空间大，正好匹配我们的视觉线。
- 避免"社区分支的二次分叉"带来的额外上游风险。

## 工程异议（记录在案，供复盘）

上一轮工程建议为 KernelSU-Next，被维护者否决。以下为当时的主要理由与现应对：

| 事项 | KernelSU-Next | 官方 KSU（现基线） | 我们的应对 |
| --- | --- | --- | --- |
| B3 模块备份/恢复 | 已内置 | 需自研 | 排入 v0.5（M4） |
| B4 App Profile 扩展 | 已有较完整版 | 仅基础版 | 自研扩展（M4） |
| SuSFS 控制界面 | 已内置 | 需自研 | 与内核线（M5）配套 |
| 新版 UI | 已重做 | 朴素 | **由我们的视觉线承担（ADR-0004）** |
| GKI 镜像模式 | 官方支持 | **官方自 v3.0 起放弃** | 由自编内核线（M5）覆盖 |

## 后果

- 正向：与生态对齐（SUSFS 补丁、DDK 工具链、社区文档）；美化与功能差异化空间更大、更"自己的东西"。
- 负向：B3/B4/SuSFS 控制界面从"白拿"变为"自研"；GKI 模式不再有官方支持，属单向门。

## 可逆性与重评触发

- 属**双向门**：我们的改动集中在独立目录、主题层与新增模块，必要时可整体回切。
- 触发条件：本机 Go/No-Go 失败（6.6 无法 LKM）；或内核线成本失控；或官方长期拒绝 LKM 上游化需求。
