# ADR-0010 改动层机制：补丁清单 + 断言（不用整文件覆盖）

- 状态：已接受（2026-09-29）
- 责任：维护者 + 构建脚本

## 背景

- 我们的分支基于上游快照（锁定 `KernelSU-3.3.0`），改动必须可追溯、可同步。
- 上游代码放在 `upstream/`（不纳入版本管理）；构建时复制到 ASCII 构建树再改。

## 决策

改动以**补丁清单**形式维护：`scripts/apply-patches.ps1` 里每条补丁 = 「文件 + 原文 + 新文 + 说明」，
应用时逐条断言：

- 已应用 → 跳过（幂等）；
- 找不到原文 → **显式报错并中止构建**（上游变更时不会静默失效）。

## 备选与被否原因

| 备选 | 否因 |
| --- | --- |
| 整文件覆盖（overlay 目录） | 上游一改就容易漏同步，问题隐蔽；本文件体积也不小 |
| `.patch` / `git apply` 系列 | 构建树无 git 历史、行号易漂移，冲突处理复杂 |
| 直接改 `upstream/` 快照 | 改动不可追溯（该目录不入库），且重新拉取即丢失 |

## 后果

- 正向：改动集中一处、带说明与断言；与上游同步时冲突立刻暴露。
- 负向：补丁多了以后脚本会变长，需要按模块分组维护（当前 2 条）。

## 现有补丁（截至 v0.0.2）

1. 更新检查指向自建更新源（未发布 ⇒ 不再误报"有新版本"）。
2. 默认主题种子色 = 水色 `0xFF2E9BD6`（开箱即用水蓝配色，落实 ADR-0004 的默认皮肤）。

## 可逆性

双向门：删除对应补丁条目即可回退到上游行为。
